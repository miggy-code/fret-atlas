# STORY-028 — Choose a new key from progress

## Friction Scorecard

| Measure | Evidence | Result |
|---|---|---|
| Steps | Practice → choose a key cell → choose activity | 3 / 2 ideal to change key; 2 including the tab switch from Explore |
| Decisions | Pick a key in the grid; select next activity | Necessary |
| Re-entry | None | 0 |
| Confirmations | None | 0 |
| Dead ends | Selecting a key updates the root control and leaves drills available | 0 |
| Hesitations | Two controls set the current key: the persistent Key selector above the board and the progress grid below it | 1 |

Live evidence: the Practice view shows a 12-key grid with cells such as “C 0/5” and a root selector above the board. Both change the current key. The grid adds useful completion feedback, while the selector is the general workspace control.

Verdict: **acceptable**. Both paths are defensible: the root selector is a workspace shortcut and the grid is the canonical progress surface. The distinction needs clearer copy.

## Take-away Pass

- Keep both key controls: they serve different contexts.
- Strengthen the Progress heading with “Choose a key to practice” and make the grid’s current-key state explicit, so it reads as a progress-aware chooser rather than duplicate settings.
- The “0 of 60 minor forms practiced” footer is useful aggregate feedback but can be muted further; it does not guide the next choice.

## The Simpler Version

1. Open Practice.
2. Choose the target key from the clearly-labelled progress grid.
3. Start the next drill or play-through.

## Clarity Issues

- A learner may not infer why the root selector and the key grid both exist. Add a one-line explanation: “Use the grid to pick a key and see your form progress.”
